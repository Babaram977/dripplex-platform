## 3. Architectural mismatch to plan around

The Figma source is a **client-side, `useState`-driven single-view switcher** (`App.tsx` holds a `Screen` union type and a `Record<Screen, ReactNode>` map, swapped via `setScreen()`), rendered inside a fixed `PhoneFrame` (390×844) or `DesktopFrame` component. `customer-web` is **Next.js App Router** — real routes, real URLs, real code-splitting, no `PhoneFrame` wrapper. Nothing here can be dropped in wholesale; every screen needs its layout/navigation logic rewritten to fit the router, same as R1.4 and R1.5 already did working from scratch. The value is in the visual/interaction design and copy, not the file structure.

## 4. Recommendation

Per the founder's instruction: **do not merge this branch, do not treat it as something `main` consumes directly.** Concretely, for the modules that actually have content:

1. **Checkout + Order Tracking (highest value):** use `checkoutScreen.tsx`/`trackingScreen.tsx` as a genuine design/interaction reference when building R1.7's checkout and tracking UI against the real Cart/Order/Payment APIs. This is net-new reference material, not a duplicate of existing work.
2. **Design tokens:** worth a dedicated, small task to evaluate formalizing `src/tokens/*` into `packages/config`'s Tailwind setup — separate from any screen-building work, since it's a cross-cutting decision (Nora should weigh in, per this project's standing design-approval pattern).
3. **Auth screens beyond what's built:** treat as a backlog, not urgent — current 5-route auth flow is functional; expanding it (2FA, trust center, sessions, etc.) is a product-scope call, not a technical blocker.
4. **Home/Marketplace/Store/Product/Cart:** skip. The real, backend-wired, bug-fixed versions from R1.5 are strictly more valuable than reference mockups of the same screens.
5. **Ride/Driver/Wallet/Merchant/Admin/Ops:** nothing to use — the placeholders confirm there's no design reference here yet. RIDE-001A proceeds exactly as planned, backend-first, uninformed by this branch.
6. **`validators.ts`:** diff against `packages/utils`/SDK validation before reusing anything from it, to avoid two disagreeing implementations of the same rules (e.g. Nigerian phone number format, PIN strength).

No code has been merged or moved into the production tree as part of this inventory — the split files used to produce it live outside the repo, in this session's scratch space only.
